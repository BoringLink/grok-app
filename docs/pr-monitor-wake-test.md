## 待更新事项

- [ ] **待更新项**：把下面 `STATUS` 的值由 `PENDING` 改成 `DONE` 后提交并推送。

```

```

`pr-monitor-acceptance` 这个检查项在 `PENDING` 时刻意失败，改成 `DONE` 后通过；因此「完成本事项」
这一次推送就是一次可预测的 CI 状态迁移（失败 → 通过），再加上一次 PR 更新事件。

## 本次优化：分支菜单「拉取请求」区

优化前的 UI：每个 PR 下面单独一行整行宽的「监视此 PR / 停止监视」按钮。

- 占高度：一个 PR 要两行（PR 行 36px + 开关行 36px）。
- 多个 PR 时不直观：开关与它属于哪个 PR 只能靠上下相邻去猜，监视多个 PR 就是一串按钮堆叠。

现在的 UI：一个 PR 一行，开关是该行尾部的铃铛图标（与 worktree 行的删除 / 显示按钮同款），
点开关不再关闭菜单；同一区里还会列出本会话在其他分支挂着的 PR，每行自带铃铛，可直接停掉。
细节见 `docs/llm-wiki/pr-monitor.md`。

### 后续修复：新 UI 真机上的三处渲染问题

按新 UI 在应用里走一遍，发现三处渲染问题，都已修掉：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| PR 行只剩汇总 `state · checks · branch`，看不到 PR 标题 | 汇总码住整行宽度，标题被压到 0 宽 | 标题留 40% 下限，汇总最多 `calc(60% - 8px)` 并自己省略 |
| 鼠标停在铃铛上，tooltip 画在菜单下面 | `.ui-tip` 用 10050，低于它要盖住的浮层（12000–14000 档） | tip 抬到顶层 14100，删掉会把 tip 压到 13050 的 `.ui-tip--modal` |
| tooltip 文案被截断 | 15 个语言里这句都偏长，tip 本身又不换行 | 铃铛的 tip 加 `.ui-tip--wrap`，同时把这句文案缩短 |

渲染已在运行中的应用里手动验证：标题与汇总各占其位、铃铛的 tooltip 压在菜单之上且文案完整。
两条守卫测试把约束钉住：`src/styles/worktreeMenuRowLayout.test.ts`、
`src/styles/tooltipLayer.guard.test.ts`。

仍然可以继续优化的点：

- 该区只列**本会话**的挂载，其他会话的挂载仍没有统一入口。
- 「最近一次更新」摘要仍只在当前分支绑定的 PR 下显示，其他行只有状态与 checks。

## 可用来触发更新的动作

| 动作 | 期望 |
| --- | --- |
| 完成待更新事项并推送 | CI 由失败转通过 → 唤醒会话 |
| 在本 PR 下追加评论 | 新评论 → 唤醒会话 |
| 修改 PR 标题 | 标题变化 → 唤醒会话 |

## 验收要看的三件事

1. 分支区出现 `test/pr-monitor-wake #<n> <标题>`，标题过长要省略。
2. 分支菜单「拉取请求」里能挂上监视，并显示「监视中」。
3. 制造一次更新后，本次会话被唤醒并主动跟进。
